01 · Why this problem matters

Personalization is not memory retrieval.

A preference can be true, stale, contextual, uncertain, or irrelevant—sometimes all within the same user history.

The problem

Users change.

An agent has to distinguish persistent evidence from temporary state and recover when an old preference stops being true.

Why it is hard

Evidence is sparse and conflicting.

Explicit statements, implicit choices and corrections carry different reliability; context can invert the correct preference.

Why common approaches fail

Retrieval can preserve the wrong thing.

Flat memory overgeneralizes, stale evidence survives preference changes, and synthetic self-training can reinforce the learner’s own mistakes.

02 · Core idea

Model the user as a moving latent state.

The system separates raw interaction evidence from inferred user state. Each preference carries confidence, provenance, context-specific values, recency, stability, conflicts and a drift signal; a relevance gate separately decides whether that state should influence the response.

Novelty position. The broad problem of evolving user preferences is not new. The narrower contribution is the combination of a context-conditioned moving user state, calibrated restraint, verified counterfactual experience, and an explicit test of synthetic data by downstream utility rather than proxy informativeness. 03 · Architecture

Three explicit loops: act, learn, recover.

Interaction evidenceexplicit · implicit · correction · context · reliability
User-state inferencerecency weighting · conflict aggregation · change detection
Moving user stateglobal + contextual values · confidence · drift · provenance
Relevance gateuse personalization only when the preference is relevant
Agent backendoffline reference path or provider-neutral foundation-model adapter
Evaluationutility · calibration · drift recovery · over-personalization · robustness
Agent loop

Observe → infer → gate → respond

Each request updates evidence, resolves the current context-conditioned state, checks whether personalization is relevant, then grounds the response only in preferences that pass the gate.

Post-training / RL-compatible loop

Failure → experience → verifier → learner

Failures generate counterfactual candidates, candidates are verified and selected, then the low-capacity reference learner is retrained and evaluated on held-out users. The reference implementation retrains a lightweight learner; the same loop can host preference optimization or RL without changing the evaluation interface.

Recovery loop

Contradiction → drift → confidence cap → state revision

Recent corrections can overturn stale evidence. Drift raises uncertainty, caps confidence, and keeps the old state from silently persisting until enough new evidence supports a revision.

Closed-loop research cycle ↺real evidence → moving state → behavior → evaluation → failures → verified counterfactuals → post-training experiment → held-out check

06 · Results

Better personalization came from evidence—not from adding more synthetic evidence.

Synthetic augmentation can fail even with correct labels. The paper upgrade isolates evidence mass as the mechanism, shows that a simple mass budget recovers most of the degradation, and adds response-level evaluation so personalization is judged by what the user actually sees.

07 · Failure analysis

The failures changed the research direction.

Synthetic evidence amplification
What happened. Oracle-correct synthetic labels still reduced held-out accuracy, and harm scaled with injected evidence mass.
Response. Add a per-user evidence-mass budget and duplicate discounting; across five seeds this recovered 94.5% of the raw degradation without pretending to outperform real-only training.
Preference drift lag
What happened. Median recovery is 10 interactions; 31.25% of controlled reversals do not recover within ten.
Response. Recency weighting, correction bonus and drift confidence caps reduce stale-state persistence; gradual-change detection remains open work.
Noisy evidence
What happened. Global inference accuracy falls from 0.953 with clean signals to 0.751 at 32% corruption.
Response. Preserve uncertainty and restraint instead of forcing confident personalization; stronger robust inference remains a limitation.
Relevance gate scale
What happened. The learned anti-personalization gate reaches 87.5% held-out accuracy, but the held-out set is only 16 controlled examples.
Response. Treat it as a mechanism proof, not an external-validity claim; the human-eval and external-model gates remain separate.

10 · Safety / limitations

A personal state is evidence—not authority.

Built in

Restraint and provenance

The system keeps confidence, source and conflict information and has a separate relevance gate so stored preferences are not automatically applied.

Built in

Privacy and adversarial checks

The implementation redacts secret-like values, validates sensitive metadata, and includes adversarial regression cases for metadata manipulation.

Permission boundary

Inference is not authorization

An inferred preference can shape a reversible suggestion; it cannot grant permission to spend money, send a message, expose private data, change an account, or execute another consequential action.

Current boundary

Irreversible actions

The benchmark never executes irreversible real-world actions. A deployment would require explicit confirmation before any consequential action.

Current boundary

Human escalation

Low-confidence or consequential cases should escalate to explicit user confirmation or human review.

The benchmark uses controlled synthetic users so the mechanism can be isolated and reproduced. Real-world user benefit, fairness, safety and external-benchmark performance still require separate evaluation.
